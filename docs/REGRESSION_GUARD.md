# 回帰防止ガイド（既存機能・UIを消さない）

このプロジェクトでは、以下を明示指示なしに削除・劣化させない。

## 1. 絶対に維持する機能
- 認証画面（メールアドレス + パスワード）
- ヘッダーのナビ（ホーム / 機能 / お問い合わせ）
- ログイン/ログアウト導線
- 未ログイン時の保護ルートリダイレクト
- タスク追加・編集・削除・完了切替
- 期限表示・期限警告表示
- 検索・フィルタ（案件/タグ/状態）
- 案件内並び替え（D&D）

## 2. 実装時のルール
- UI改修時は「見た目変更」と「データ処理変更」を同時に行わない。
- 1コミット1目的で変更し、差分を小さく保つ。
- 既存コンポーネントを削除する変更は禁止（明示指示がある場合を除く）。
- app/page.tsx の既存UIブロックは、削除ではなく内部処理の差し替えで対応する。

## 3. 変更ごとの必須確認
- npm run lint
- npm run build
- 手動確認:
  - /auth: ログイン・新規登録が表示される
  - /: 未ログインなら /auth へ遷移
  - ログイン後: タスク画面が表示される
  - ヘッダー: ナビ + ログアウト導線が見える
  - CRUD / 検索 / フィルタ / D&D が動く
  - ログアウト後: /auth へ戻り、保護ページが見えない

## 4. 作業前チェック
- git status で未コミット差分を確認
- 影響ファイルを事前に列挙
- 変更後に上記の必須確認を実行

## 5. NG例
- 画面を一新するために既存UIを丸ごと置換
- 認証ロジックの一時削除
- D&Dやフィルタ等の既存機能を「一旦外す」

## 6. 例外
- ユーザーから明示的に「削除してよい」と指示があった場合のみ削除可。
